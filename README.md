# US-25 — Simulated Reviews API (F5) and Agency File Generator (F4)

> **User Story**
> As a data engineer, I want a simulated reviews API (F5) and an agency
> file generator (F4), so that reputation and duplicate-booking logic
> have realistic input data to work against later.

**Jira:** B0-94 (US-25), Epic 6 — *Simulated data sources and seed*
**Subtasks:** B0-95 (TASK 1), B0-96 (TASK 2)

## Acceptance criteria

- **AC1** — Given the multi-language and duplicate-review requirements of
  F5, when the simulated reviews API returns data, then reviews in
  Spanish, English, and Portuguese are present, including some duplicated
  across platforms.
- **AC2** — Given the cross-channel duplicate requirement of F4, when the
  agency file generator runs, then at least one booking appears
  duplicated across two channels with slight name differences.

Both are implemented and verified end-to-end — see [Verifying the
acceptance criteria](#verifying-the-acceptance-criteria) below.

## TASK 1 — Simulated reviews REST API (F5)

### What it does

Generates a synthetic, reproducible dataset of guest reviews (fixed seed)
and serves it through a small FastAPI application, matching the F5 spec
from the project brief: *"REST paginated API: rating, text, date, hotel,
platform"* (~300 reviews/day as a reference volume).

Reviews are generated in **Spanish, English and Portuguese**, and a
configurable fraction (~8% by default) are **duplicated across
platforms** — the same review text (with a small variation, as a real
cross-posted review would have) appears under two different platforms
(`booking`, `tripadvisor`, `expedia`, `google`) for the same hotel and
guest, with a `duplicate_of` field pointing back to the original
`review_id`.

### Step 1 — Install dependencies

```bash
pip install fastapi uvicorn
```

### Step 2 — Run the API locally

```bash
cd reviews_and_agency_simulator
uvicorn app.main:app --reload --port 8001
```

### Step 3 — Explore it

Interactive docs (Swagger UI), auto-generated by FastAPI:

```
http://localhost:8001/docs
```

Available endpoints:

| Method | Path | Purpose |
|---|---|---|
| GET | `/health` | Basic healthcheck, returns total review count |
| GET | `/reviews` | Paginated list, with optional filters |
| GET | `/reviews/{review_id}` | Fetch a single review |
| GET | `/hotels/{hotel_id}/reviews` | Convenience shortcut, same as filtering by `hotel_id` |

Query parameters on `/reviews`:

- `page`, `page_size` — pagination (`page_size` max 200)
- `hotel_id` — e.g. `hotel-001`
- `platform` — one of `booking`, `tripadvisor`, `expedia`, `google`
- `language` — one of `es`, `en`, `pt`
- `only_duplicates` — `true` to list only reviews flagged as a duplicate
  of another one (useful to check AC1 quickly)

### Example requests

```bash
curl "http://localhost:8001/reviews?page=1&page_size=10&language=pt"
curl "http://localhost:8001/reviews?only_duplicates=true"
curl "http://localhost:8001/hotels/hotel-001/reviews"
```

### Design notes

- The dataset is generated **once, in memory, at process startup**, with
  a fixed seed (`SEED = 2026` in `app/main.py`) — restarting the server
  always returns the exact same data, which matters for reproducible
  demos and grading.
- `TOTAL_REVIEWS = 900` and `DUPLICATE_RATE = 0.08` are the two knobs
  that control volume and duplicate density; both are plain constants at
  the top of `app/main.py`.

## TASK 2 — Agency file generator with cross-channel duplicates (F4)

### What it does

Generates one weekly CSV file per travel agency (~15 agencies, per the
F4 spec), alternating between **two different column layouts** to
simulate the "agencies with different formats" requirement from section
5.2 of the brief.

For the duplicate-booking requirement (AC2), the generator doesn't
invent an isolated duplicate — it reaches into the **real output of the
US-24 channel-manager simulator** and clones one of its `created`
reservations into an agency row: same hotel, dates within ±1 day (the
tolerance defined by business rule RN-08), same amount, but with a
**guest name carrying a small, realistic variation** (swapped name
order, a middle initial instead of a full name, a one-letter typo, or a
different capitalization).

### Step 1 — Make sure US-24 output exists

```bash
cd ../channel_manager_simulator
python3 event_generator.py --reservations 30 --seed 42 --output output/events.jsonl
cd ../reviews_and_agency_simulator
```

### Step 2 — Run the generator

```bash
python3 generate_agency_files.py \
  --f2-events ../channel_manager_simulator/output/events.jsonl \
  --output-dir output/agency_files \
  --seed 7 \
  --bookings-per-agency 12 \
  --duplicate-count 3
```

CLI flags:

| Flag | Default | Meaning |
|---|---|---|
| `--f2-events` | `../channel_manager_simulator/output/events.jsonl` | Source of real reservations to clone duplicates from |
| `--output-dir` | `output/agency_files` | Where the CSVs (and the summary file) are written |
| `--seed` | `7` | Reproducibility seed |
| `--bookings-per-agency` | `12` | Regular (non-duplicate) bookings generated per agency |
| `--duplicate-count` | `3` | How many US-24 reservations get cloned as cross-channel duplicates |

### Step 3 — Check the output

```
output/agency_files/
├── viajafacil_week.csv
├── solymar_tours_week.csv
├── ... (15 files total)
└── _generation_summary.json   # which rows are duplicates, and of which US-24 reservation
```

`_generation_summary.json` is the fastest way to confirm AC2 without
opening every CSV by hand — each entry lists the agency, the duplicate
row's booking id, the original `reservation_id` from US-24, and both
guest-name spellings.

### Design notes & known limitations

**Guest name derivation.** The F2 event schema (defined and validated in
US-12) does not carry a guest name — only `guests: {adults, children}`.
To simulate "duplicate booking with slight name differences" without
touching that already-closed contract, this generator **deterministically
derives** a guest name from each `reservation_id` (same seed → same name,
always) and treats that as the "real" guest for that reservation. If F2
adds a real guest name to its payload later, only one function needs to
change: `_derive_guest_name()` in `app/agency_files.py`.

**Missing currency is left as a hook, not implemented here.** A fraction
of agency rows are generated with an empty `currency` field on purpose —
this lines up with the "currency not stated in agency files" data-quality
defect from section 5.3, but **the configurable injection rate for that
defect belongs to US-26** (which depends on US-14). This generator only
leaves the field nullable so US-26 can act on it without friction; it does
not implement any injection logic itself.

**Two column layouts, not fifteen.** Agencies alternate between layout A
and layout B (different column names/order) rather than each having a
fully unique format. This was a deliberate scope call — it demonstrates
the "different formats" requirement without hand-crafting 15 parsers'
worth of edge cases for a simulator.

## Verifying the acceptance criteria

### AC1 — reviews API

```bash
# with the server running on :8001
python3 - <<'EOF'
import json, urllib.request

all_items, page = [], 1
while True:
    with urllib.request.urlopen(f"http://127.0.0.1:8001/reviews?page={page}&page_size=200") as r:
        d = json.load(r)
    all_items.extend(d["items"])
    if page >= d["total_pages"]:
        break
    page += 1

langs = {r["language"] for r in all_items}
dups = [r for r in all_items if r["duplicate_of"]]
assert {"es", "en", "pt"} <= langs
assert len(dups) > 0
print(f"OK: {len(all_items)} reviews, languages={langs}, duplicates={len(dups)}")
EOF
```

### AC2 — agency files

```bash
python3 - <<'EOF'
import json
summary = json.load(open("output/agency_files/_generation_summary.json"))
dups = summary["duplicates_created"]
assert len(dups) >= 1
for d in dups:
    assert d["real_guest_name"] != d["agency_guest_name"]
    print(f"OK: {d['hotel_id']} | {d['original_reservation_id']} "
          f"'{d['real_guest_name']}' vs '{d['agency_guest_name']}'")
EOF
```

Both checks were run against this exact code during development: 972
reviews generated (3 languages present, 72 cross-platform duplicates),
and 3 confirmed cross-channel duplicates against real US-24 reservations.
